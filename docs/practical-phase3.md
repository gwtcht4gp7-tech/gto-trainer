# 实用候选第三阶段：尺度模型、独立测试与隔离 HTTP 接口

2026-10-29。保留上一阶段检查点 07246a9。这一阶段没有改写生产求解接口、采集器、玩家档案或模型，也没有重启线上服务。

## 从诊断推进到两个可运行模型

第一版不再用硬编码的“下注越大就越强”规则：从 match 100 的 71 手公开 PHH 学习行动/尺度的平滑似然表，冻结模型后才评估 match 101 的 92 手。翻后平均范围对数评分相对原模型为 -0.0331 nats，近似区间 [-0.1090, 0.0429]。没有通过，明确保留失败结果，不晋级。

第二版保留原模型的整手路线、位置和收缩后的玩家统计，只学习五个小修正：下注尺度与牌力、极化程度、过牌、跟注价格、同花听牌。系数受界限与正则约束，没有学习动作 EV，也没有把它命名为 GTO。match 100+101 合计 163 手作为训练材料；612 个翻后底牌标签参与训练。冻结参数后，另用此前未看过的 match 102 测试。

训练时真实底牌只作监督标签。推理函数只接收玩家公共资料、之前的公开行动、当前公共牌和冻结模型；不接收真实对手底牌。普通推理不导入 PokerKit 或训练器，不启动训练，也不写模型。源码 tests 包含梯度数值校验、零修正等价、尺度敏感性和信息隔离检查。

## 独立测试的结果与限度

- 测试材料共 73 手；全部街有 1,576 个单对手标签。
- 有效翻后统计来自 **32 手、226 个标签**，不是 73 个独立翻后样本。
- 翻后平均对数评分差为 +0.01251 nats，按手聚合的近似区间 [-0.00983, 0.03485]。
- 翻前修正为零。全部街的按手平均差为 -0.000080 nats。
- 两个模型的 densityGate 都未通过；deploymentApproved 始终为 false。

这表明第二版没有第一版那样大的负向点估计，但仍不能证明它比原模型更好。不能把跨零区间说成已经提升，也不能根据这一个 match 外推到其他对手。没有继续用 match 102 调参。后续确认应换独立 match，并扩大训练和有效翻后样本。

只读审查发现训练的短筹码 toCall 已封顶，而历史重建原先未封顶；已统一为实际支付额，并补短筹码测试。修复后重训参数和该测试评分逐位一致，说明这一批训练/评分未受该分支影响。修复前的模型和评分仍在本地保留。它是规则口径修复，不是根据测试成绩选择新参数。

## 决策回放与可调用接口

practical_replay.py 新增显式 --range-model 参数；默认仍用原范围模型。传入修正模型时，会联合抽样全部活跃对手，再经原启发式与规则/不确定性门控输出。所有原始建议仍是 publishable=false，不能用两个模型的自报 EV 或动作变化次数证明收益提升。

match 102 的全部 177 个翻后决策点各用三个种子回放，同时保存原模型对照，共 1,062 次。修正版有 22 次候选动作与原模型不同，权益差最大约 10.94 个百分点；这些是模型敏感性，不是正确率。最终修复版本重新完成 531 次候选运行，全部成功，单次耗时 286.1–422.3ms；518 次可展示候选动作均通过独立 PokerKit 执行，另外 13 次被资格或不确定性检查保留。完整证据在本地 v2-replay.json/v2-legality.json，汇总随源码备份。

新增 practical_preview_server.py，默认单独使用 localhost:8894，POST /preview 接收 decisionId 与完整 request。固定模型由启动参数指定，HTTP 输入不能指定文件路径。接口限制单个并发、拒绝过期请求、丢弃超时建议，返回对应 decisionId；始终标记 isolated_preview、publishable=false、recommendationReady=false。没有接管 8900/8892。

benchmark_preview_http.py 在临时端口进行真实客户端 HTTP 联测，结束后关闭服务。固定选择翻牌/转牌/河牌各前六个决策，共 18 个请求全部成功，最终一轮最慢约 0.37 秒，包含 HTTP、工作进程启动、范围估计、联合权益及 Node。**不包含游戏采集或现有桥接**，不代表线上完整延迟已验收。

联测曾暴露推理误导入训练依赖，导致未配置 PokerKit 时失败；已把训练导入移至训练入口并新增回归测试。不能省略这类联测而仅依赖训练环境通过。
