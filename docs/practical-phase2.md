# 实用候选第二轮：规则、多人权益与公开牌谱

2026-10-28。本轮产物是隔离的离线候选，尚未接入 8900 页面，没有替换线上代码、重启服务、训练模型或改写玩家记录。

## 已落实的变化

- 保留简单启发式作为候选核心，所有参与者的范围来自当前决策之前的公开行动，联合抽样排除撞牌并计算分池份额。没有使用稀疏全街模型的随机续局。
- 新增单独的 guardedPreview 输出：不沿用旧启发式自报的“高置信度”和混合频率；原始建议仅留在 rawDecision 供审计。
- 能免费过牌时不建议弃牌；小于最低额度的翻后下注提高至合法下限；超筹码下注不直接截成全下。
- 河牌上跟注会结束下注时，必要时退回跟注/弃牌子问题，报告相应条件 EV 与抽样区间，并明确没有评估加注收益。其他街不把直接摊牌 EV 冒充整手 EV。
- 当权益抽样区间足以改变启发式动作，或跟注 EV 区间跨零时，不输出确定动作。区间只反映抽样误差，不能覆盖对手范围估错的偏差。
- 完整账本必须与活跃对手 ID、筹码一致；边池资格无法确定时不给行动候选。

## 独立可核算的有限子问题

预先固定 48 个河牌最终跟注/弃牌场景，涵盖 2/3/5/6 人，每人 4 个加权组合，3 个拟合种子，每次 4,000 个样本。独立 JavaScript 评估器枚举全部合法联合组合，另有每场景 20,000 次独立留出发牌。两个策略共享发牌，只比较“看一位对手”与“计算所有对手”的区别。

| 指标 | 结果 |
|---|---:|
| 场景 / 策略运行 | 48 / 144 |
| 因人数修正改变动作 | 37 次 |
| 单对手版本平均有限子问题遗憾 | 3.926bb/场景 |
| 联合版本平均有限子问题遗憾 | 0bb/场景 |
| 场景聚类后的平均配对差 95% 区间 | 0.407 至 7.445bb |
| 进程内估计与决策最大耗时 | 89.0ms |

这证明该封闭子问题中不能随意忽略其他对手。它不是实战赢率、bb/100，不能外推为全街多人策略优越；各人数子组也没有全部获得显著差异。对手范围在此是已声明的测试先验，不是估计器已经学会了真实玩家。

另外单独放入 3 个临界压力场景：真实跟注 EV 约 -0.132/0/+0.134bb。未经门控时动作随种子翻转，联合版本也会犯小错；没有把这些场景混入前述均值。新增门控将全部 9 次临界运行标记为不确定。原始结果仍保留，没有删掉失败样本。

## 公开牌谱回放

来源为 [PHH dataset 的 Pluribus 牌谱](https://github.com/uoftcprg/phh-dataset/tree/main/data/pluribus/100)，使用其连续编号 0–9 十手牌，按编号选择，没有按建议效果筛选。金额和行动合法性借助 [PokerKit 0.7.7](https://pokerkit.readthedocs.io/en/stable/notation.html)。数据原文、URL、逐手 SHA256 和 MIT 许可均保留在此目录。

导入范围明确限制为标准六人起手、无 ante、SB/BB、单牌面 NLHE；牌中可以减少至单挑。不支持的格式直接拒绝。只导出当时行动者自己的底牌、当前公共牌与此前公开行动。观测动作单独存作元数据，未作为最优策略标签；其他底牌、后续牌面、后续行动和最终输赢都不进入决策请求。牌谱没有实时时戳，时间截止检查仍标为不可核验；导入器另用严格的行动前缀保证不越过决策点。

| 最终固定版本回放 | 结果 |
|---|---:|
| 公开牌谱 / 决策点 | 10 / 100 |
| 每点种子 / 总运行 | 3 / 300 |
| 请求成功 / 输入拒绝 / 超时 / 错误 | 300 / 0 / 0 / 0 |
| Python 启动至返回耗时 | 343.9–508.6ms |
| PokerKit 实际执行候选动作 | 300 合法，0 失败 |
| 原始两种权益版本动作不同 | 3 次 |
| 原始联合版本跨种子动作不稳定 | 0/100 个决策点 |

62 个翻前、19 个翻牌、13 个转牌、6 个河牌决策点；存活人数 2–6 人。这里通过的是状态、规则和本批抽样稳定性，不是策略准确率。计时不含生产 HTTP、采集及桥接开销，不能据此称线上 3–4 秒已经验收。

回放实际抓到旧启发式建议 119bb 加注但只有 83bb 筹码，以及 0.66bb 下注低于 1bb 最低额。最终候选分别限制为河牌跟弃比较、调整到最低合法下注；另将一次免费时弃牌改为过牌。前述 300 次独立规则执行验证针对修正后的输出，而非只重复自身金额检查。

旧版“高置信度”字段和种子间动作稳定，均不证明对手范围正确。例如 A2 两对面对多条街的强势路线，其范围估计仍可能有偏差；不能拿实际高手弃牌或一次输赢给未执行动作定价。因此本轮还没有证明复杂候选在一般实战中比简单基线更强，未自动恢复旧版或晋级线上。

## 工程检查与恢复

45 项 Python 检查通过，其中 33 项随隔离候选提供，12 项为原工程数学回归。候选副本独立运行其 33 项检查也通过。只读审查发现了 PHH 双人盲位反转和短盲注金额问题：导入范围已缩至六人起手，初始投入取 PokerKit 实际下注，补了拒绝双人格式与短盲注测试；MP/HJ 命名按现有引擎统一。

并行压测曾暴露旧 taskkill 清理超时及一个测试 Node 遗留；已核实 PID、父 PID 与固定测试命令后清除。超时清理改用本次拥有的工作进程及后代的 Windows 原生接口，在相同并行负载下重测通过。最终没有该人工测试命令的遗留进程。超时结果丢弃建议，清理耗时单独报告；清理可能超过返回目标的限制仍保留。

原始归档异常手牌再测 12 次：9 次合法快照成功，3 次底池账本不一致被拒绝。AJ 深筹码仍为小尺度启发式开池，46/KQJ 在无需跟注时过牌、面对 2.5bb 时弃牌，均无旧的异常大额行动。这是指定样本回归，不是它们已求得 GTO 的证明。

离线运行不连接游戏、不写模型或玩家数据库。候选在 candidate/，其 source-manifest.json 记录复制的源码指纹；不需要回滚线上。继续工作的重点是验证对手路线与下注尺度如何影响范围，并在固定对手与同一发牌下比较策略价值，而非继续扩大未经验证的全街搜索树。
